kPay

Accept kPay payments on your website

Sign in as a merchant and open API integration. Your administrator must approve your merchant account, enable payment providers, and keep the receiving account and collection phone active.

1. Save server credentials

Create an API key, configure your HTTPS webhook URL, and save the one-time signing secret. Keep both secrets in your website server environment. Customer browsers receive only checkout links.

KPAY_BASE_URL=https://kpay-six.vercel.app
KPAY_API_KEY=your_merchant_key
KPAY_WEBHOOK_SECRET=your_webhook_secret
KPAY_PROVIDER=nagad

2. Create a payment from your server

Call POST /api/v1/payments with Authorization: Bearer YOUR_KEY and Content-Type: application/json. Calculate the amount from your saved order; never trust a browser price.

{
  "order_id": "ORDER-1001",
  "amount": "100.00",
  "currency": "BDT",
  "provider": "nagad"
}

A successful response is HTTP 201. Amounts are decimal BDT strings.

{
  "id": "payment_uuid",
  "order_id": "ORDER-1001",
  "amount": "100.00",
  "currency": "BDT",
  "provider": "nagad",
  "status": "pending",
  "expires_at": "ISO timestamp",
  "created_at": "ISO timestamp",
  "checkout_url": "https://kpay-six.vercel.app/checkout.html#payment=...&token=..."
}

Reuse the same order ID for retries. The same order and details return the existing payment; changed amount or provider returns HTTP 409. Redirect the customer to checkout_url. Checkout shows the assigned receiving number, instructions and exact amount, collects the customer's sending number and transaction ID, and waits for receipt verification.

3. Confirm payment on your server

Call GET /api/v1/payments/PAYMENT_ID with your API key, or look up your order using GET /api/v1/payments?order_id=ORDER-1001. Compare payment ID, order ID, amount and currency with your saved order. Fulfil only when status is verified.

Statuses: pending, verified, review_required, expired, rejected, cancelled. Expired or disputed payments need merchant support. A submitted transaction ID does not confirm receipt.

4. Receive signed webhooks

kPay sends payment.verified to your configured public HTTPS endpoint.

{
  "id": "stable_event_uuid",
  "type": "payment.verified",
  "created": "ISO timestamp",
  "payment_id": "payment_uuid",
  "order_id": "ORDER-1001",
  "amount": "100.00",
  "currency": "BDT",
  "status": "verified"
}

Headers: X-KPay-Event, X-KPay-Timestamp (Unix seconds), X-KPay-Signature: v1=HEX. Verify HMAC-SHA256 over timestamp + '.' + rawRequestBody using the webhook secret and a constant-time comparison. Reject timestamps more than five minutes old or in the future. Parse JSON only after signature verification. Verify payment status on the kPay API, match the saved order and amount, and mark it paid in a database transaction.

Deduplicate using the event ID and payment ID. Return 2xx only after durable processing. Retries retain the same event ID. Delivery stops after 12 attempts or 72 hours; monitor API integration for failures. Automatic delivery happens on verification, with scheduled retries. Keep a periodic server-side status check as recovery if a webhook is delayed.

Optional custom checkout

Your server can submit customer details using POST /api/v1/payments/PAYMENT_ID/claim with {"sender":"01712345678","transaction":"ABC123XYZ"}. Continue polling or wait for the webhook; this request alone never authorizes fulfilment.

Errors and troubleshooting

Errors are JSON: {"error":"message"}. HTTP 401: missing/revoked key or suspended merchant; 403: forbidden access; 404: payment not found or owned by another merchant; 409: conflicting order or consumed transaction; 422: invalid input or no eligible collection account; 429: rate limit (30 requests/minute per server IP and merchant); 503: service unavailable.

No eligible account: ask your administrator to activate the account and approve the phone, SMS permission, physical SIM and sender template. No verification: check the sending number, transaction ID, exact amount, expiry and captured provider receipt.

Runnable website example

Download Node.js website example

Requires Node.js 24. Save the file as merchant-server.mjs, set the server environment variables above, and run node merchant-server.mjs. Open http://127.0.0.1:8080. To receive webhooks, deploy it behind your own public HTTPS website and configure https://your-site.example/webhooks/kpay. The example uses a fixed BDT 100 item and a local SQLite order database. Adapt product pricing and authentication to your own website.

Provider transfer occurs in the customer's mobile wallet. kPay verifies SMS evidence and credits the merchant ledger; external payouts follow the separate settlement process.
